# 스토어 등록 — 붙여넣기만 하면 되는 것들

**업로드는 사람이 한다.** AI는 여기까지 준비하고 멈춘다 (`CLAUDE.md` §5).
이 문서는 업로드 폼 앞에서 글을 쓰지 않아도 되게 만드는 것이 목적이다.

---

## 먼저 알아야 할 것 — SDK가 실제로 보내는 것은 적다

디컴파일로 확인한 사실이다. 폼에 칸이 보여도 코드가 안 읽는 것이 있다.

| 대상 | SDK가 보내는 것 | 나머지는 |
| --- | --- | --- |
| **mod.io** | 이름 · **한 줄 요약** · 로고 이미지 · 공개 여부 | 긴 설명·태그·의존성은 **mod.io 웹사이트에서** |
| **창작마당** | 제목 · 설명 · 태그 · 공개 범위 · 썸네일 · 파일 ID | — |

- mod.io 업로드에는 **버전도 변경 로그도 안 실린다.** SDK가 그 칸을 비워 보낸다
- mod.io 폼의 `URL`·`Tags` 입력칸은 **화면에 없고 코드도 안 읽는다**
- 새 mod.io 프로필은 **비공개로 생성된다.** 웹에서 공개로 바꿔야 보인다
- 창작마당 공개 범위를 안 건드리면 **비공개가 기본값이다**

## ⚠ 먼저 해야 하는 한 가지

**모드 SDK 창의 `Mod Management` 탭에서 `Build Mod`(또는 `Build and Install Mod`)를 한 번 눌러야 한다.**

우리 빌드는 `Editor/build.ps1` → `CliBuild` → `ModBuilder.BuildMod`로 직접 들어가는데, 이 경로는
SDK의 `ModPaths.asset`에 경로를 등록하지 않는다. 지금 그 목록이 비어 있어서 **창작마당 탭이
"No built mod found"로 막힌다.** GUI로 한 번 빌드하면 등록되고 그 뒤로는 풀린다.

## 창작마당 (Steam Workshop)

**설명문은 이미 저장소에 있다.** 모드 루트의 `description.txt`를 SDK가 자동으로 읽는다
(GUI 설명 칸을 비워두면 그 파일이 쓰인다). 고칠 일이 있으면 그 파일을 고친다.

절차:

1. 스팀을 켜둔다 → `PugMod → Open Mod SDK Window` → `Steam Workshop` 탭 → `Initialize Steam`
2. `Select a Built Mod`에서 NoBreakZone
3. **Title:** `No Break Zone`
4. **Description:** 비워둔다 (`description.txt`가 쓰인다)
5. **File ID:** 새로 올리는 것이면 `0` 또는 공란. 갱신이면 기존 ID
6. **Mod Visibility:** 처음에는 `Private`로 올려 확인한 뒤 `Public`으로 바꾸는 편이 안전하다
7. **Tags** — 종류별로 하나씩 추가한다

   | Tag Type | 고를 것 |
   | --- | --- |
   | Category | `Quality of Life`, `Item` |
   | AppType | `Client`, `Server` |
   | AccessType | **`Script (Elevated Access)`** |

   > 마지막 것은 선택이 아니다. 우리 설정이 `accessesExtraAssemblies: 1`이라 그 태그가 맞는
   > 표기다. 기획서 §12의 "배포 시 서버 측 모드로 표기한다"는 AppType에 `Server`를 넣는 것으로
   > 지킨다 — 다만 클라이언트도 오브젝트를 그려야 하므로 `Client`도 함께 넣는다

8. **Select Thumbnail for Mod** → 아래 이미지
9. `Upload to Steam Workshop` → 돌아오는 **published file ID를 기록**한다
   (`Editor/NoBreakZone_Steam.asset`에도 저장된다)

> **제목이 빌드 산출물을 덮어쓴다.** Title 값이 빌드된 폴더의 `ModManifest.json`의 `displayName`에
> 써진다. 다시 빌드하면 원래 값으로 돌아가므로, 업로드 직전에 빌드하고 바로 올린다.

## mod.io

1. SDK 창의 `Mod.IO` 버튼으로 로그인 (이메일 → 보안 코드). 로그인해야 업로드 탭이 나타난다
2. `Select a Built Mod`에서 NoBreakZone
3. **Description** (여기 칸은 mod.io의 **한 줄 요약**으로 간다) — 아래 요약문
4. **Select Thumbnail for Mod.io** → 아래 이미지
5. `Register at mod.io` → 프로필이 **비공개로** 생성된다
6. `Upload to mod.io` → 프로젝트에서 임시 폴더로 다시 빌드해 올린다
7. `Go to mod page` → **웹사이트에서** 긴 설명·태그·의존성·공개 전환을 한다

## 붙여넣을 글

### mod.io 요약 — 영어

업로드 폼의 `Description` 칸에 들어가는 것이 이것이다. 긴 설명이 아니라 **한 문단짜리 요약**이고,
mod.io가 목록에서 모드 이름 밑에 보여준다.

```
Place a pylon, press E, and everything in the square around it stops being destructible — chests, walls, floors, machines. Press E again and your base is ordinary, so you can remodel it.
```

### mod.io 요약 — 한국어

```
파일런을 설치하고 E를 누르면 그 주변 사각형 안의 모든 것이 부서지지 않습니다. 상자도, 벽도, 바닥도, 기계도 마찬가지입니다. 다시 E를 누르면 평소대로 돌아가 기지를 고칠 수 있습니다.
```

### 긴 설명 (영어)

모드 루트의 [`description.txt`](../../description.txt) 내용을 그대로 쓴다. 창작마당은 그 파일을
자동으로 읽고, mod.io 웹사이트에는 사람이 붙여넣는다.

### 긴 설명 (한국어)

```
내 곡괭이, 내 폭탄, 빗나간 공격에 기지가 부서지는 것을 막습니다.

파일런을 설치하고 E를 누르면 그 주변 사각형 안의 모든 것이 부서지지 않습니다. 상자도, 벽도,
바닥도, 기계도, 파일런 자신도 마찬가지입니다. 다시 E를 누르면 평소대로 돌아가 기지를 고칠 수
있습니다. 보호는 전역도 영구도 아닙니다. 내가 고른 자리에서, 내가 켜는 것입니다.

[무엇이 들어 있나]

  파일런         설치하고 E. 켜짐 상태는 저장하고 불러와도 유지됩니다.
  파일런 작업대   아래 셋을 만드는 곳. 자동화 작업대에서 제작합니다.
  파일런 렌즈     들고 있으면 켜져 있는 모든 파일런의 경계가 보입니다.
                 그 외에는 어떤 방법으로도 범위가 표시되지 않습니다.
  파일런 리모콘   멀리 떨어진 파일런을 켜고 끕니다. 벽 너머로 막혔을 때를 위한 것입니다.

[켜져 있는 동안]

범위 안의 어떤 것도 부술 수 없습니다. 벽과 광석도 포함입니다. 이것은 실수가 아니라 의도입니다.
실수로 날려먹을 수 없는 기지는 실수로 고칠 수도 없는 기지이므로, 파내고 싶을 때는 파일런을
끄면 됩니다.

농사와 드릴 자동화는 예외라서 켜둔 채로도 정상 작동합니다. 부서질 때가 아니라 맞을 때마다
자원을 내놓는 것들, 특히 드릴이 캐는 광석 덩어리는 절대 보호하지 않습니다. 그것을 보호하면
자원이 무한 복제되어 세이브가 영구히 망가지기 때문입니다. 이 규칙이 이 모드의 다른 무엇보다
우선합니다.

[멀티플레이]

무엇이 보호되는지, 스위치가 무엇을 하는지는 서버가 결정하므로 모든 플레이어에게 동일하게
보입니다. 소유권 개념은 없습니다. 누가 설치했든 파일런은 그 안의 것을 보호합니다.

[설정]

  protectionDiameter  21     파일런 하나가 덮는 사각형의 한 변 길이(타일)
  blockMobDamage      true   끄면 몹과 폭발은 보호된 것을 부술 수 있게 됩니다
  showRangeWithLens   true   렌즈를 들었을 때 경계를 표시합니다
  remoteReachTiles    30     리모콘의 사거리

소스와 문의: https://github.com/LeeShinYeoung/no-break-zone
MIT 라이선스.
```

## 이미지

두 스토어 모두 **`.png` / `.jpg`만** 받는다. SDK는 형식만 검사하고 크기는 안 본다.
mod.io가 서버에서 **1280×720 · 640×360 · 320×180**으로 다시 렌더하므로 **16:9**가 맞고,
**1280×720 이상**으로 준비한다. 너무 크면 mod.io가 거부한다(`ModLogoTooLarge`).

`Editor/Docs/art/store_thumbnail.png`가 그 규격으로 생성되어 있다.
`Editor/Docs/art/sprites.py`가 만들며, 다시 뽑으려면 그 스크립트를 실행한다.

## 올리기 전에 — 점검 목록

**순서: 빌드 → 아래 점검 → release → deploy.** release(태그 + 깃허브 릴리스)와 deploy(mod.io·창작마당
업로드)는 다른 일이고 한 명령에 묶지 않는다. deploy는 사람이 한다.

- [x] `powershell -File Editor/build.ps1` 종료 코드 0
- [x] `Player.log`에 우리 경고가 없는지 — 없다. `missing: Items` 0건.
      `couldn't load … asmdef` 한 줄은 배포된 다른 모드들도 똑같이 내는 무해한 줄이다
- [x] 컴파일 경고 0 — `FindObjectOfType`의 CS0618을 없앴다
- [ ] `logictest.ps1`·`verify.ps1` 초록 — 유니티 테스트 러너는 라이선스로 막혀 이 둘이 관문이다
      (`workflow.md`). 배포할 때마다 새로 돌린다
- [x] 아래 "게임 속 확인 목록" — 자원 복제(1번)를 포함해 인게임에서 확인했다. 다만 항목별 결과가
      안 남은 번호가 있다 (`status.md`)
- [x] **기존 월드**에서 로드 — 사람의 본 월드에서 계속 플레이해 왔다. 세이브가 깨진 적 없다
- [x] 멀티플레이 — 데디서버를 띄우고 클라이언트로 붙어 자가 테스트를 돌렸다.
      **서버 권한 코드가 네트워크를 건너 검증된 것은 이 경로다**
- [ ] 사람 둘이 동시 접속 — 엄밀히는 안 해봤다. 다만 이것이 노리는 위험(서버가 판정하고
      클라이언트가 받는 경로)은 위에서 이미 훑었으므로 **배포를 막을 사유로 보지 않는다**

> **이 목록이 한동안 틀려 있었다.** 증거가 쌓인 뒤에도 갱신되지 않아 몇 주 동안 "미검증"으로
> 남아 있었고, 그 때문에 배포가 실제보다 멀어 보였다. **체크리스트는 일이 끝날 때마다 갱신한다.**
> 안 그러면 목록이 현실이 아니라 과거를 가리킨다.

## 게임 속 확인 목록 (체크포인트 1, 2026-08)

기능이 다 붙은 뒤 사람이 윈도우에서 한 번에 확인하려고 만든 목록이다. 배포 전 관문으로 썼다.
항목 옆 메모("1차", "이번 수정" 등)는 그때 기준이다. 결과가 기록되지 않은 번호는 `status.md`에 있다.

1. **자원 복제가 없는가** — 기획서 §6이 다른 무엇보다 우선한다고 못박은 항목이고,
   **바닥·벽 보호가 들어오면서 판정이 넓어졌으므로 이제 더 중요하다.**
   - **켜진 파일런 범위 안에서**: 광석이 드릴로 정상 고갈되는가, 곡괭이로 정상 채굴되는가,
     작물 수확이 정상인가 ← **벽은 안 부서지는 게 정상이지만 광석은 부서져야 한다**
   - 범위 **밖** 벽은 평소대로 캐지는가
   - 파일런을 끄면 범위 안 벽도 다시 캐지는가
2. ✅ **1차 통과** — 자동화 테이블에 `Pylon Workbench` 레시피가 떴다 (`slots=7, ours=6,
   categories=0`). 2차에서는 **이름이 `Pylon Workbench`로 뜨는지** 본다 — 1차에서는
   `missing: Items/NoBreakZone.Workbench`였다. **인벤토리 아이콘이 그려지는지도 같이 본다**.
   바닐라 6개도 그대로 있어야 한다
3. **작업대를 설치하고 E로 열리는가.**
   1차에서는 아무 반응이 없었고, 원인은 로직 프리팹에 `Interaction.LocalInteractableAuthoring`이
   없던 것이었다. 그래도 안 열리면 다음 용의자는 `RotationAuthoring` — SDK에는 있고 우리는
   의도적으로 뺐다
4. **작업대에서 파일런이 제작되는가.** 목록에 파일런·렌즈·리모콘 3종이 다 보이고 이름이 뜨는가
5. **보이는가, 그리고 크기가 맞는가** — **파일런도 작업대도 한 타일이어야 정상이다.**
   넘치면 아트 크기가 다시 어긋난 것이고, 아예 안 보이면 `research.md` 12장의 프리팹 참조
   형태를 의심한다 (`m_address`는 자동 검사 대상이라 용의선상에서 내려갔다)
6. **파일런이 꺼진 채로 설치되는가** (기획서 §5). 이때는 아무것도 보호하지 않아야 한다
7. **E로 켜지고 꺼지는가. 보석이 같이 빛나는가**
   ← 변형 매핑 확인 (`research.md` 13장의 미검증 추론). 안 바뀌면 대안이 적혀 있다.
   **실루엣은 절대 안 튀어야 한다** — 두 변형이 같은 텍스처를 쓰므로 튀면 다른 원인이다
7-1. **켤 때 짧은 빛과 소리, 끌 때 약한 역방향 연출이 나는가**
7-2. **기지에 들어설 때는 아무 소리도 안 나는가** ← "처음 반영" 가드 확인.
   나면 파일런이 스트리밍될 때마다 울리는 것이다
7-3. **이펙트가 범위 경계까지 퍼지지 않는가** (기획서 §7 — 퍼지면 렌즈가 필요 없어진다)
8. **범위가 맞는가** — 켠 뒤, 파일런 기준 10타일 안 상자는 안 부서지고 **밖 상자는 부서지는지**
9. **껐을 때 상자가 다시 부서지는가** ← **4단계의 핵심.** 안 되면 보호 해제가 안 도는 것
10. **원래 무적이던 게임 오브젝트는 여전히 안 부서지는가** ← 보호 해제의 안전장치 확인.
    코어·보스 구조물을 켰다 껐다 하며 때려본다
11. **껐다 켜면 다시 보호되는가**
12. **세이브/로드를 넘어 켜짐 상태가 유지되는가** (기획서 §5)
13. **켜진 파일런이 폭탄·곡괭이에 안 부서지고, 끄면 회수되는가** (기획서 §6)
14. **파일런 두 개를 겹쳐 놓고 하나만 끄면 보호가 유지되는가**
15. **나중에 놓은 파일런도 듣는가** — 상자를 먼저 놓고 그 옆에 파일런을 설치해서 켠다.
    `[NoBreakZone] active pylons` 로그가 뜨고 그 상자가 보호되면 재판정이 도는 것이다
16. 멀티플레이가 가능하면: **다른 플레이어 화면에서도 스프라이트가 바뀌는가**
17. 작업대에서 **렌즈가 제작되는가.** 인벤토리에서 **안 겹쳐지는가** (design.md §4)
18. **렌즈를 들면 켜진 파일런 주위에 닫힌 사각 윤곽 하나가 보이는가**
    ← 사다리 무늬·이중선이면 변 4개가 아니라 옛 타일 방식이 남은 것.
    **네 변이 갈라져 보이면** 평면 안 회전 각도가 틀린 것 (`PlaceEdge`의 오일러 각)
    ← 안 보이면 재질 문제를 제일 먼저 의심한다 (`research.md` 14장). 벽을 뚫고 보이는 것도 같은 원인
19. **내리면 사라지는가.** 인벤토리·지도를 열면 사라지는가
20. **꺼진 파일런은 경계선이 안 보이는가**
21. **경계선이 실제 보호 범위와 맞는가** — 선 바로 안쪽 상자는 안 부서지고 바깥은 부서지는지
22. 파일런이 여러 개 보일 때 **눈에 띄게 버벅이지 않는가** (이제 파일런당 4개)
22-1. **모서리에 틈이 없는가.** 선이 실제 경계와 맞는가 (선 바로 안쪽 상자는 안 부서지고 바깥은 부서지는지)
23. 마커가 **기지를 이상하게 만들지 않는가** (기획서 §7: 그러면 사용자가 모드를 지운다)
24. 작업대에서 **리모콘이 제작되는가**
25. **커서를 파일런에 올리고 우클릭하면 켜지고 꺼지는가**
    ← 안 되면 `SecondInteract_Pressed` 가정을 의심한다 (`research.md` 15장)
26. **E로 누른 것과 결과가 완전히 같은가** — 스프라이트·이펙트·보호 전부
27. **30타일 밖에서는 안 되는가.** 파일런이 아닌 것에 우클릭하면 아무 일도 안 나는가
28. **벽으로 둘러싼 파일런을 끌 수 있는가** ← 리모콘이 존재하는 이유 (design.md §4)
29. **여러 타일을 차지하는 바닐라 설치물**(상자·침대 등)을 경계에 걸쳐 놓으면 보호되지 않는가
    (기획서 §6). 우리 작업대가 1×1이 되면서 모드 안에는 다중 타일 물건이 없다 — **바닐라로 본다**
30. **완전히 안에 넣으면 보호되는가**
31. **파일런 둘에 나뉘어 걸친 물건은 보호되는가** ← 합집합 해석 확인
32. **파일런을 끄면 그 다중 타일 물건도 풀리는가** ← 거는 쪽/푸는 쪽이 어긋나지 않았는지
33. `Player.log`에 `no ObjectInfo for …` 경고가 뜨는가 ← 뜨면 그 오브젝트는 1×1로 취급된 것
34. **설정 파일이 생기고 네 항목이 다 보이는가** (`Player.log`의 `[NoBreakZone] config:` 줄)
35. **보호 범위를 11로 바꾸면 파일런을 껐다 켜지 않고도 좁아지는가**
36. **몹 피해 차단을 끄면** 몹이 상자를 부수고, **플레이어 곡괭이는 여전히 안 통하는가**
    ← 유일하게 추론에 기댄 부분
37. 범위 표시를 끄면 렌즈를 들어도 안 보이는가. 리모콘 사거리를 5로 줄이면 짧아지는가
38. **언어를 한국어로 바꿔도 아이템 이름이 (영어로라도) 뜨는가** ← 빈칸이면 구조가 틀린 것

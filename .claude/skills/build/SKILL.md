# build

## 먼저 확인: 지금 이 머신에서 빌드가 되는가

**빌드는 윈도우에서만 된다.** 유니티 프로젝트는 윈도우 머신에 있고(경로는 `Editor/build.ps1`의
`-ProjectPath` 기본값), 맥 체크아웃은 문서·계획·코드 편집용 미러다.

`uname`이 `Darwin`이면 빌드를 시도하지 말고 **여기서 멈추고** 사람에게 이렇게 알린다.

> 코드는 여기까지 됐습니다. 빌드는 윈도우에서 해야 합니다.
> 유니티 에디터를 닫고 `powershell -File Editor/build.ps1` 를 실행한 뒤,
> 출력 마지막 줄(BUILD OK / BUILD FAILED)을 알려주세요.

빌드 결과를 받으면 아래 "결과 해석"으로 이어간다.

## 절차 (윈도우)

1. **유니티 에디터를 닫는다.** 배치 모드는 프로젝트 락을 두 번 잡을 수 없다.
   `Temp/UnityLockfile`이 있으면 스크립트가 종료 코드 `2`로 거부한다.
2. 실행:
   ```powershell
   powershell -File Editor/build.ps1
   ```
   기본값은 `build.ps1` 맨 위 `param` 블록에 있다 — Unity `6000.0.59f2`, 유니티 프로젝트 경로,
   게임의 `CoreKeeper_Data\StreamingAssets\Mods` 경로.
   다르면 `-Unity` / `-ProjectPath` / `-ExportPath` 로 넘긴다.
3. 스크립트가 로그 마지막 40줄을 찍는다. 전체 로그는 `%TEMP%\nbz_build.log`.

## 결과 해석

| 종료 코드 | 의미 | 다음 행동 |
| --- | --- | --- |
| `0` | 빌드 성공, `...\Mods\NoBreakZone\` 에 설치됨 | 사람에게 인게임 확인 요청 (아래) |
| `1` | 빌드 실패 | `%TEMP%\nbz_build.log` 에서 컴파일 에러를 찾아 고친다 |
| `2` | 유니티 에디터가 열려 있음 | 에디터를 닫고 재실행. 코드 문제가 아니다 |

## 빌드 성공 후 — 반드시 검증을 요청한다

**빌드 성공은 검증 완료가 아니다.** 사람에게 *무엇을 어떻게* 확인할지 구체적으로 알린다.
막연히 "테스트해 주세요"라고 하지 않는다.

요청에 포함할 것:

1. 게임을 재시작한다 (모드는 게임 시작 시 로드된다 — 핫 리로드는 미검증)
2. **이번 변경이 무엇을 바꿔야 하는지** — 관찰 가능한 문장으로
3. **무엇이 망가지지 않았어야 하는지** — 특히 광석·벽·항아리 채굴과 작물 수확.
   설치물 보호가 자원 채굴까지 막으면 자원 복제나 진행 불가로 이어진다
4. 확인 후 `Player.log` 를 보내달라고 요청

로그 경로:
```
%LOCALAPPDATA%Low\Pugstorm\Core Keeper\Player.log
```

로그에서 볼 것: `[NoBreakZone] loaded`(모드 로드), `[NoBreakZone] PROTECT ...`(보호 적용),
그리고 예외·`couldn't load` 경고.

## 주의

- 번들에는 modPath 아래 `Editor/`·`Conf/`·`Localization/`·`.cs`·`.dll` **밖의 모든 자산**이
  실린다. 빌드 후 새 `couldn't load` 경고가 보이면 루트에 파일을 늘린 게 원인이다.
- 피처 브랜치 안이라면 미검증 상태로 커밋해도 된다. 메시지에 `미검증`을 명시한다.
  게이트는 커밋이 아니라 머지다 — `main`에 넣는 건 `/land` 뿐이고 그 스킬이 검증을 묻는다.
- 검증이 끝나면 `/land` 로 넘어간다.

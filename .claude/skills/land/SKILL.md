# land

피처 브랜치 하나를 **PR 생성 → 머지 → 정리**까지 한 번에 끝낸다.
이게 `main`에 코드가 들어가는 **유일한 경로**다.

## 절대 하지 않는 것

- `--squash` · `--rebase` 머지 — 피처 안의 커밋이 `main` 이력에 남아야 한다
- `main`에서 직접 실행
- deploy(mod.io·창작마당 업로드) 관련 동작 일체 — `/release` 이후 사람이 한다
- 검증 상태를 묻지 않고 머지

---

## 1. 전제 확인

```bash
git branch --show-current
git status --porcelain
git log --oneline main..HEAD
```

- **`main`이면 중단한다.** "피처 브랜치에서 실행해야 합니다"라고 알리고, 어떤 브랜치를
  땄어야 했는지 제안한다. 되돌리려면 사람이 판단해야 하므로 임의로 브랜치를 만들지 않는다
- **작업 트리가 더러우면** 무엇이 남았는지 보여주고 커밋할지 물어본다
- **`main..HEAD`가 비어 있으면** 머지할 게 없다. 중단한다

## 2. 검증 확인 — 여기가 게이트다

**반드시 묻고, 답을 받아야 다음으로 간다.**

> 게임에서 무엇을 확인하셨나요?

빌드는 윈도우 전용이라 이 스킬이 직접 빌드하지 않는다. 사람의 답변이 유일한 근거다.

- **"문서만 바꿔서 게임 검증이 무의미하다"도 유효한 답이다.** 게이트는 *게임을 했는가*가
  아니라 *검증 상태가 기록됐는가*다. 답변을 그대로 PR 본문에 옮긴다
- **"아직 안 해봤다"면 멈춘다.** 머지하지 않고, 무엇을 확인하면 되는지 구체적으로 알린다
  (`Editor/Docs/design.md`의 해당 항목 기준). 사람이 그래도 머지하라고 하면 PR 본문에
  **`미검증`을 명시**하고 진행한다
- 자원 복제(광석·작물)에 영향을 줄 수 있는 변경이면 그 확인을 먼저 요청한다

## 3. 푸시

```bash
git push -u origin "$(git branch --show-current)"
```

## 4. PR 생성

본문은 `.github/pull_request_template.md`의 4개 절을 채운다.

| 절 | 채우는 법 |
| --- | --- |
| 무엇을 바꿨나 | `git log main..HEAD` 에서 요약. 해당하면 `design.md` 항목 명시 |
| 왜 | 커밋 본문의 근거. 조사 기반이면 `research.md` 장 번호 |
| 사람이 게임에서 확인한 것 | **2단계 답변을 그대로.** 지어내지 않는다 |
| 위험 / 남은 것 | 알려진 한계·미확인 항목. 없으면 "없음" |

```bash
gh pr create --base main --title "<브랜치의 대표 변경>" --body "$(cat <<'EOF'
...
EOF
)"
```

제목은 커밋 규약과 같게 **영문 `type: subject`**, 본문은 한글.

## 5. 머지

```bash
gh pr merge --merge --delete-branch
```

저장소 설정이 `delete_branch_on_merge: false`라 `--delete-branch`를 **반드시** 붙인다.
붙여도 원격만 지워질 수 있으니 다음 단계에서 로컬을 확인한다.

## 6. 정리

```bash
git checkout main
git pull
git branch -d <피처브랜치>          # 실패하면 머지가 안 된 것이다. 확인 후 알린다
git branch -a | grep <피처브랜치>   # 로컬·원격 모두 사라졌는지
```

## 7. 보고

- PR 번호와 URL
- `main`에 들어간 머지 커밋
- 브랜치 정리 결과
- **`Editor/Docs/status.md` 갱신이 필요한지 판단**해서 필요하면 알린다.
  기능 단계가 진행된 PR이면 대개 필요하다

---

## 실패했을 때

| 증상 | 대응 |
| --- | --- |
| `gh pr create` 가 "no commits between" | 브랜치가 `main`과 같다. 커밋했는지 확인 |
| 머지 충돌 | 자동 해결하지 않는다. 충돌 파일을 보여주고 사람에게 알린다 |
| `git branch -d` 실패 | 머지가 실제로 안 됐다. 강제 삭제(`-D`) 하지 말고 원인을 보고한다 |
| 푸시 거부 | 원격이 앞서 있다. `git pull --rebase` 는 사람 확인 후에만 |
